# 비슷한 사진 검색과 중복 검증의 분리

확인: 2026-10-17 02:51 KST. 공개 자료 조사이며 구현·사진 평가·정확도 개선 측정은 수행하지 않았다.

## 도입 판단

**DINO는 후보 순위에 유지하고, 중복 판정은 별도 가벼운 검증 단계로 둔다.** 같은 장소·사람·옷이라는 의미가 비슷한 사진과 원본의 재압축·리사이즈·크롭 사본은 다른 문제다. 임베딩 점수 하나를 양쪽 의미에 사용하지 않는다. 검색 결과는 넓게 유지하고, 검증 근거가 부족하면 `비슷함/중복 미확정`으로 남긴다. 새 대형 모델 도입은 이 단계에 필요하지 않다. 이는 아래 원리에서 도출한 **설계 제안**이며 성능 보장은 아니다.

## 방법별 확인 사실과 판정 한계

| 방법 | 원문에서 확인한 작동 원리 | 중복 판정에서의 한계 — 원리에 따른 추론 |
| --- | --- | --- |
| pHash | OpenCV 구현은 32×32 회색조로 축소하고 DCT 저주파 8×8을 이진화한다. 비교는 Hamming distance다. | 압축·해상도 차이 후보를 싸게 거르는 데 적합하다. 축소·회색조에서 사람의 작은 동작·의류 색·작은 물체 변화가 사라질 수 있다. 같은 hash도 원본 동일성을 증명하지 못한다. 크롭·회전·배치 변경의 일반적 불변성도 없다. |
| SSIM | 원 논문은 기준 영상과 왜곡 영상의 국소 밝기·대비·구조를 비교하는 full-reference 품질 측정이다. | 대응 위치를 맞춘 뒤 비교해야 한다. 정렬 전 크롭·이동은 다른 내용처럼 보일 수 있고, 전체 평균은 작은 중요 피사체의 변화를 배경에 묻을 수 있다. 조명 변화가 허용할 편집인지 별도 사진인지 SSIM이 결정하지 않는다. |
| ORB + RANSAC homography | ORB는 FAST keypoint, 방향을 보정한 BRIEF binary descriptor, 다중 scale을 사용한다. 매칭 후 RANSAC은 한 변환과 일관된 inlier를 찾는다. | 크롭·회전·일부 원근 변화의 대응 위치를 찾는 보조 수단이다. **같은 배경의 다른 행동 사진도 배경 keypoint만으로 homography가 성공할 수 있다.** 반복 무늬·적은 texture·심한 흐림·비평면 입체 물체·시점에 따른 가림은 오매칭/실패 원인이 된다. 변환 성공은 중복 증거의 일부일 뿐이다. |

핵심 원문 5개:

1. [OpenCV pHash 실제 구현](https://github.com/opencv/opencv_contrib/blob/4.x/modules/img_hash/src/phash.cpp) — 알고리즘과 비교 함수 확인. `pHash`라는 이름만 같은 다른 구현의 threshold를 가져오지 않는다.
2. [Wang et al., SSIM 원 논문](https://www.cns.nyu.edu/pub/eero/wang03-reprint.pdf) — full-reference/국소 구조 비교의 정의와 압축 품질 평가 범위를 확인. 논문이 중복 판정 성능을 보장하는 것은 아니다.
3. [OpenCV ORB 공식 설명](https://docs.opencv.org/4.x/d1/d89/tutorial_py_orb.html) — 학습 가중치 없는 binary descriptor, 회전/scale 처리와 Hamming 비교 확인. 문서의 오래된 SIFT 특허 설명은 현재 권리 판단에 재사용하지 않았다.
4. [OpenCV Feature Matching + Homography](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html) — 대응점, RANSAC inlier mask, 변환 추정 확인. 예제의 숫자 설정은 제품 기준값으로 권고하지 않는다.
5. [OpenCV 라이선스](https://opencv.org/license/) — 4.5.0 이상 Apache2.0. 실제 포함하는 제3자 구성요소의 고지·조건은 패키징 시 따로 확인한다.

## 가장 작은 적용안 — 제안

1. **동일 파일과 시각적 사본을 구분한다.** 파일 SHA256 일치는 동일 bytes 확인용이다. 다른 인코딩·메타데이터·EXIF 방향의 파일은 hash가 달라도 시각적으로 같은 사진일 수 있다. 디코딩 비교는 EXIF 방향·색 공간·alpha 합성·크기 정책을 먼저 고정한다. canonical pixel 일치도 그 정규화 정책 안의 동일성으로 표기한다.
2. **DINO 후보에 pHash와 정렬된 국소 비교를 붙인다.** 같은 프레이밍 후보는 정규화한 공통 화각에서 SSIM/차이 지도를 확인한다. pHash만 낮다고 확정하지 않는다. 전체 평균 외에 공간별 차이와 변화 면적을 보존해 작은 행동·의류 차이를 놓치는지 평가한다. 이때 `같은 의류/개체, 다른 구도`는 유용한 검색 결과지만 중복으로 합치지 않는다.
3. **크롭 후보에만 선택적으로 ORB+RANSAC을 쓴다.** descriptor를 후보별로 재사용하고, 양방향 매칭·inlier 비율과 공간 분포·양쪽 겹침 영역·변환의 수치 안정성을 기록한다. 정렬 후 **유효 겹침 영역만** 비교하고 warp 바깥 채움색은 점수에 넣지 않는다. 배경에만 대응점이 몰렸거나 피사체 영역이 변했으면 미확정으로 돌린다. 피사체를 안정적으로 식별할 수 없다면 자동 확정 범위를 좁힌다.

작은 크롭은 한쪽 전체와 다른 쪽 일부가 일치하는 `사본 후보`일 수 있으나, 원본의 나머지 내용까지 같다고 증명하지 않는다. 작은 로고/무늬 하나의 일치와 사진 전체의 파생 사본은 구분해야 한다. 동작이 다른 연속촬영, 같은 상품을 다른 각도에서 찍은 사진은 배경/개체가 일치해도 별개 사진으로 보존한다. 재조명·강한 편집·부분 합성은 허용 변환의 제품 정의가 먼저 필요하며 무조건 같은/다름으로 일반화할 수 없다.

쌍별 중복 관계를 연결한 것만으로 그룹 전체를 자동 병합하지 않는다. 부분 크롭 A↔B, B↔C가 성립해도 A↔C의 같은 내용은 보장되지 않는다. 대표 이미지와 각 구성원의 직접 근거를 유지하고 불확실한 연결은 검색 연관 관계로 남긴다.

## CPU·Android·iOS 비용을 별도로 판단

이 방법들은 새 학습 가중치가 필요 없고 OpenCV CPU 경로가 있다. 그러나 pHash 비교보다 ORB 추출·다수 후보 매칭·RANSAC·warp 비용이 크므로 전체 사진의 모든 쌍에 적용하지 않는다. 후보 수·작업 해상도·keypoint 수·반복 상한을 고정한 뒤 실제 기기에서 지연·메모리를 측정해야 한다. 이 조사에서는 실행·속도를 측정하지 않았다.

- Android: [공식 배포 안내](https://opencv.org/opencv4android-usage-models/)는 4.9.0부터 Maven Central AAR를 제공하며 contrib가 필요 없을 때 권고한다. ORB/features2d와 homography/calib3d는 기본 모듈 경로다. **img_hash는 contrib**이므로 기존 pHash가 있다면 재사용하는 편이 의존성 증가를 피한다. AAR 크기·ABI별 용량은 실제 채택 산출물 확인 전 미확인이다.
- iOS: [공식 iOS 설치 안내](https://docs.opencv.org/4.x/d5/da3/tutorial_ios_install.html)는 framework와 contrib 별도 빌드를 설명하지만 스스로 오래된 정보를 포함할 수 있다고 경고한다. 현재 Xcode/기기/simulator 패키지 호환은 미검증이다. Swift에 C++ 라이브러리를 연결하는 adapter·배포 크기·빌드 유지 비용이 별도로 남는다.
- 공통: 논문이 공개되어 있다는 사실과 논문의 예제 코드를 배포할 수 있다는 조건은 다르다. SSIM 알고리즘 정의를 활용하더라도 채택 구현의 라이선스·색 공간·window·data range·border 정책을 고정하고 플랫폼 간 동일성을 따로 확인해야 한다.

## 평가가 먼저 필요한 항목

같은 원본의 재압축/리사이즈/회전/크롭/밝기 편집과, **같은 배경의 다른 행동**, **같은 옷·상품의 다른 사진**, 반복 무늬·작은 피사체·흐림을 구분해 측정한다. 중복 확정 precision/오병합률을 우선하고, 검색 recall·미확정률·처리 비용도 함께 본다. 원본/촬영 사건 단위로 calibration과 holdout을 분리한다. 소규모 자료에 맞춘 거리·SSIM·inlier threshold 추천은 하지 않는다. 검증 실패는 비중복의 증명이 아니라 증거 부족으로 처리할 수 있어야 한다.

조사 근거: 실제 Exa 검색 1회 → 일반 웹 교차검색 2회 → Exa 원문 fetch 4회를 수행했다. 첫 대량 응답의 도구 출력 일부가 잘려 ORB·homography·SSIM을 제한 길이로 다시 읽었다. 처음 Android 문서 URL은 CRAWL_NOT_FOUND였고 일반 검색으로 찾은 위 공식 배포 안내를 실제 fetch해 복구했다. 원문 이미지를 내려받거나 로컬 사진/코드/비공개 경로를 검색 서비스에 보내지 않았다. 문서 작성 외 다운로드·설치·소스 변경은 없다.
