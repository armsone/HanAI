# Pillow12.3.0 RGB8 bicubic → DINO224 계약
확인: 2026-10-17 07:51 KST. 원문 조사만 수행했으며 구현·설치·이미지 접근·픽셀 비교는 하지 않았다.
고정 원문: Pillow12.3.0 commit `bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d`, Transformers5.20.1 commit `0ea877911a11499053df677befd4b35b172ff502`. 아래 계약은 **PIL backend·RGB8·전체 box·reducing_gap=None**에 한정하며 torchvision/플랫폼 기본 bicubic과 동일하다고 가정하지 않는다.

1. **크기:** [HF helper L296–311](https://github.com/huggingface/transformers/blob/0ea877911a11499053df677befd4b35b172ff502/src/transformers/image_transforms.py#L296)의 `new_short=256`, `new_long=int(256*long/short)`. 양수의 int는 floor이며 nearest round가 아니다. `(H',W')` 방향을 복원한다. [PIL backend L548–570](https://github.com/huggingface/transformers/blob/0ea877911a11499053df677befd4b35b172ff502/src/transformers/image_processing_backends.py#L548)가 이 helper와 PIL resize를 호출한다.
2. **커널:** [Resample.c L47–62](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L47), `a=-0.5`, `t=abs(x)`; `t<1: ((a+2)t-(a+3))*t*t+1`; `1≤t<2: (((t-5)t+8)t-4)*a`; 나머지0. Catmull–Rom 형태이며 support=2([L86](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L86)). 수학적 동치식이어도 floating 연산 재배열로 계수 양자화 경계를 넘을 수 있어 원 연산 순서를 유지한다.
3. **좌표·축소 anti-alias:** [L198–204/L231–248](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L198). 축별 입력 box `[in0,in1]`, 출력 길이 `M`일 때 `s=Double(in1-in0)/M`, `f=max(s,1)`, `support=2*f`, 출력 j의 center=`in0+(j+0.5)*s`. 입력 pixel i의 weight=`kernel((i-center+0.5)/f)`. full box에서는 입력 index 좌표가 `(j+0.5)*s-0.5`인 half-pixel 배치다. 축소 시 고정4tap이 아니며 radius가2*s로 넓어진다. box 인자는 원 C에서 float이고 계수 계산은 double이다.
4. **경계:** [L235–262](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L235). 시작=`max(0,trunc(center-support+0.5))`, 끝 exclusive=`min(N,trunc(center+support+0.5))`; C int cast는 **0방향 절삭**이다. 범위 밖 tap을 버리고 실제 남은 weight 합으로 각각 나눈다(합≠0). replicate/mirror/zero-padding이 아니다. 음수 lobe를 제거하지 않는다. 정규화 전 weight를 계산한 순서대로 double 합산한다.
5. **정수 계수:** [L93/L269–283](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L269), `PRECISION_BITS=32-8-2=22`, `Q=2^22`. 정규화 weight w에 대해 `k=trunc(w*Q+0.5)`(w≥0), `trunc(w*Q-0.5)`(w<0). ties-away-from-zero이며 Swift/Kotlin 기본 bankers rounding을 쓰면 안 된다. 양자화된 k 합을 Q에 맞춰 다시 보정하는 코드는 없다.
6. **RGB8 pass 출력:** [L344–361](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L344), 채널마다 `acc=2^21+Σ(pixel8*k)`; [clip8 L175–180](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L175)는 `acc >>22`를 lookup으로0…255에 clamp한다. 이 부호 있는 shift·clamp와 동등하게 구현해야 한다. float 합을 끝에 한 번 반올림하는 방식이 아니다.
7. **두 pass와 중간 반올림:** [L806–847](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/libImaging/Resample.c#L806), 보통 horizontal→vertical이며 중간 이미지는 같은 RGB8 mode다. 따라서 **가로 결과를 uint8로 반올림·clamp한 뒤 세로 pass**한다. 중간 float 유지/2D 한 번 합산은 동일하지 않다. 크기가 바뀌지 않는 축은 pass를 생략하며 전체 크기/box가 같으면 copy([Image.py L2397–2402](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/PIL/Image.py#L2397)).
8. **12.3.0 wrapper 예외:** [Image.py L2432–2438](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/PIL/Image.py#L2432): 원 `H>100*W`이고 `H'<H`이면 먼저 `(원W,H')`로 vertical resize, 그 결과를 `(W',H')`로 horizontal resize한다. 극단적으로 세로가 긴 이미지의 **vertical→horizontal** 예외를 누락하지 않는다. pass별 RGB8 반올림 때문에 순서는 중요하다. `reducing_gap`을 지정하면 integer reduction이 추가되지만 이 계약은 None이다([L2414](https://github.com/python-pillow/Pillow/blob/bb1d8e8ab8d29048624d96e3ee53cecf7c13d13d/src/PIL/Image.py#L2414)).
9. **center crop:** [HF L489–504](https://github.com/huggingface/transformers/blob/0ea877911a11499053df677befd4b35b172ff502/src/transformers/image_transforms.py#L489), `top=(H'-224)//2`, `left=(W'-224)//2`; `[top,top+224)×[left,left+224)`를 잘라낸다. 양수 차이에서는 floor로 왼쪽/위쪽에 치우친1pixel 배치다. shortedge256 이후라 padding 분기는 필요하지 않다. RGB8 crop은 새 보간 없이 slice한다.
10. **모델 FP32 입력:** [고정 DINO processor](https://huggingface.co/facebook/dinov2-small/blob/ed25f3a31f01632728cabb09d1542f84ab7b0056/preprocessor_config.json)는 위 크기·resample3과 mean(.485,.456,.406)/std(.229,.224,.225)를 명시한다. [rescale L119–123](https://github.com/huggingface/transformers/blob/0ea877911a11499053df677befd4b35b172ff502/src/transformers/image_transforms.py#L119)는 `float64(pixel)*0.00392156862745098` 후 float32로 내린다. [normalize L418–440](https://github.com/huggingface/transformers/blob/0ea877911a11499053df677befd4b35b172ff502/src/transformers/image_transforms.py#L418)는 mean/std도 float32, 뺄셈 후 나눗셈이다. byte→float32÷255 한 줄의 반올림과 같은지 가정하지 않는다. RGB→NCHW를 유지하며 resize 전에 정규화하지 않는다.

**구현 경계:** RGB8이 이미 같다는 전제다. EXIF방향·ICC/색공간·alpha 합성·원본 decoder는 이 resample 계약 밖이므로 플랫폼별 decode 차이를 resize 오류로 돌리지 않는다. Android Bitmap filtered scale/Apple CGContext high quality라는 이름만으로 위 계약과 같다고 처리하지 않는다. 픽셀·입력tensor·최종vector 동일성은 후속 실제 비교 대상이다.
