기존 판정을 고정한 38쌍(비슷함7/다름31), 동일한 48개 cached JPEG 입력:

작은 회고 비교이며 일반 사진 정확도나 중복 삭제 정밀도가 아니다. 비슷한 쌍7개 중5개는 빈 장면으로, 사람만 남긴 사후 진단은 9쌍/양성2개에 불과하다. 검색 순위 개선을 미검증 자동 중복 제거 임계값으로 사용하지 않는다.

최초 DINO 비교는 영상에서 ffmpeg512로 만든 RGB, Vision은 cached full JPEG를 사용했다. 이번에 이 차이를 확인해 **동일 JPEG로 재비교**했고 AP/AUC 개선은 그대로였다. 두 입력 경로 사이 cosine 거리의 최대 차이 약0.088은 모델 변환 오차가 아니며, 기존 임계값 승계 근거로 쓸 수 없다. 비교 원본과 정정 기록을 모두 로컬에 보존했다.

## 범위와 복구

CoreMLTools9.0/Torch2.14/NumPy2.5 첫 변환은 scalar 변환 오류였다. 기존 환경을 보존하고 Torch2.7/Transformers4.52.4/NumPy1.26.4 별도 변환 환경에서 재개했다. 원 bicubic 위치 보간 연산이 지원되지 않아 정확한 고정224 결과만 상수화했다. nearest 등 다른 식으로 대체하지 않았다.

Swift/시스템 Core ML 컴파일러의 캐시·임시 작업 경로 권한 실패는 동일 작업의 정식 권한 요청으로 복구했고, 변환 성공에서 멈추지 않고 실제 48개 추론까지 실행했다. 합성 자료 생성기의 마지막 상태 출력 오류는 NumPy 정수 JSON 직렬화였으며, 생성 완료된 입력 파일을 보존하고 상태 출력만 고쳤다.

이 비교는 이미 같은 RGB8인 입력에서 시작한다. 플랫폼 JPEG/HEIC 디코더·EXIF 방향·색공간·alpha 처리, 실제 앱 경로·기기 메모리·지연은 별도로 확인해야 한다. 병행 실행이 있었으므로 이 실행시간으로 모바일 속도 향상률을 주장하지 않는다. 개인 원본·픽셀·특징 벡터는 외부 에이전트나 Git에 전송하지 않았다.

## 보수적인 기존 사진 판정 보정

별도 원본 세션에서 일정 간격으로 고른 32개 사진을 먼저 눈으로 판정해 44쌍(비슷함8/다름36)을 고정했다. 그 다음 특징을 계산하고, 보정 자료에서 오판 없이 비슷한 쌍을 3개 이상 유지하는 거리 경계를 한 번 선택했다. 고정 cosine 거리 상한은 `0.06911703708590078`이다. 사용자 정답이 아닌 팀장의 시각 판정이며 일반 사진용 보편 임계값이 아니다.

기존 평가 38쌍에 상한을 바꾸지 않고 적용했다. 실제 앱의 휘도 지문 함수를 그대로 실행한 비교다. 촬영 시각·화면비·얼굴 수·최종 묶음·사진 길이 전체를 재현한 앱 정확도로 해석하면 안 된다.

| 시각 지문 판정 | 비슷한 쌍 유지 | 다른 쌍을 비슷하다고 오판 | 놓친 비슷한 쌍 |
| --- | ---: | ---: | ---: |
| 기존 지문 | 7/7 | 31/31 | 0 |

두 누락은 모두 사람이 있는 양성 쌍이다. 개선은 배경만 비슷한 사진의 잘못된 묶음을 줄이는 방향이며 사람 사진 유사도를 해결했다는 뜻이 아니다. 적용 경계는 기존 판정의 보수적 거부 보조다. 원본·장수·입력 순서·사진 길이 하한을 보존하고, 한 배치의 특징이 모두 유효하지 않으면 전체 배치에 기존 방식을 사용한다. 개인정보인 픽셀·특징·자료 경로는 공개하지 않는다.
